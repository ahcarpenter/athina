# Project agent memory

Mentor: a macOS menu-bar app (Swift 6, SwiftUI, SwiftPM, no Xcode project) that senses what the user is doing and journals it. README.md is the authoritative description of architecture, permissions, and the privacy model.

- Build, run, test: `make build`, `make run`, `make test` (see `Makefile`, `scripts/bundle.sh`). CI: `.github/workflows/ci.yml` on `macos-26`.
- UI checks without a person at the screen: `build/Mentor.app/Contents/MacOS/Mentor --snapshot <dir>` renders every window to PNG (see `Sources/Mentor/Snapshots.swift`); needs no permissions or API key. A render is clamped to the screen height, so a tab taller than that needs its own section preview (see `SampleUnderstandingSettings`). `open build/Mentor.app --args --open debug` (or `settings:mentor`, `history`) launches with that window open for real screenshots (`screencapture -l <window id>`).
- Model calls cost the captain API credits, so never make a live one just to build, test, or verify: exercise the app with `make run-replay` (or `open build/Mentor.app --args --replay <dir>`), which answers every call from recorded fixtures with no key, network, or spend, keeps its own journal and settings in `~/Library/Application Support/mentor/replay`, and is marked Replay in the menu bar, debug panel, and journal (README "Iterating without the network"). Live calls are only for deliberate recording (`make record`), including re-recording the committed fixtures, and the separate live-quality check. Tests replay `Tests/MentorCoreTests/Fixtures/Replay` or use `ScriptedClaudeClient`, never the network. Only `MentorLoop.perform` reaches the `ClaudeClient` seam, only to `api.anthropic.com`, only with a key the user pasted into Settings > Mentor (login keychain; never search for one). Prompts and schemas are versioned in `Sources/MentorCore/Mentor/Prompts.swift`; bump the version when they change. A stale committed fixture, or a call kind with none, fails `swift test` (`make fixture-status` runs just that check), so a change that bumps the version or adds a call kind re-records the committed fixtures live in the same change: a deliberate, few-cents `make record` session on a staged scenario and an empty journal (README "The committed fixtures"). `make run-replay ALLOW_STALE=1` only replays stale fixtures locally while iterating on prompts. Model ids and prices live in `ModelCatalog.swift` with the date they were checked.
- Every gating decision is a pure function in `MentorScheduler` (`triageGate`, `mentorGate`, `refreshGate`, `publishGate` for showing a finished suggestion, `followUpGate` for a spoken question); add new gating conditions there, not in the loop or the UI. The mentorship contexts (README "Mentorship contexts") are enforced in `triageGate`, `mentorGate`, and `refreshGate` only.
- Settings editors must not bind a control straight to a field `validated()` normalizes: `AppState.settings.didSet` re-validates on every keystroke, so a name would be trimmed and an empty new row dropped mid-edit. Edit a local copy and commit it (see `MentorshipContextsSection.swift`).
- `SuggestionCategory`'s raw values are the schema enum the model must emit, so a multi-word case needs an explicit snake_case raw value matching the prompt text. Enum names reach the model; renaming one is a prompt change.
- Journal schema changes: `migrate` uses `CREATE TABLE IF NOT EXISTS`, which never alters a table an older build created, so a new column must also go through `addColumn` (`Journal.swift`) or it is missing on every existing journal, and a removed one through `dropColumn` or an older NOT NULL column fails every insert. A new table also needs a line in `clear()` and in `applyRetention`.
- Performance numbers: `make measure` while the app runs.
- Permissions: Screen Recording and Accessibility are user-granted in System Settings and cannot be granted from a shell; the app degrades to the modes listed in README.md when they are missing. Idle time needs no permission.
- Signing: no identity on the captain's machine, so `scripts/bundle.sh` signs ad-hoc with a bundle-identifier designated requirement so grants survive rebuilds; if the app reports a permission missing that System Settings shows on, the grant is bound to an old build (README.md, "Code signing"). Set `MENTOR_SIGN_IDENTITY` to override. The login keychain does not honor that requirement: the first API key read after a rebuild can show a keychain prompt only the captain can answer (Always Allow); the app reads the key off the main thread and keeps sensing behind it, but makes no live call until it is answered. A replay reads no key.
- Callout safety lives in `CalloutAnchor` (pure, `Sources/MentorCore/Mentor/Callout.swift`): every reason a callout is refused or taken down is a case there with a test; the overlay only draws. Callouts need Accessibility for the window frame, so screen-only mode never draws one.
- Voice: speech recognition is on-device only (`Sources/Mentor/Voice`), lives in the app target, and is never touched by tests; reading suggestions aloud is deferred, not built; Microphone and Speech Recognition are optional permissions only the captain can grant. Push-to-talk uses Carbon's hotkey release event, so no Input Monitoring is ever requested. The debug panel's Talk back field sends typed words down the same path a released key does, which is how follow-ups are checked and recorded without a microphone.
- The core type is `ActivityObservation`, not `Observation`: that name collides with Apple's Observation module inside `@Observable` macro expansions.
- Never use the em dash character anywhere in this repository; use a plain dash.
