# Project agent memory

Athina: a macOS menu-bar app (Swift 6, SwiftUI, SwiftPM) that senses what the user is doing and journals it. README.md introduces it, CONTRIBUTING.md owns the development loop, and `docs/<topic>.md` owns the detail (architecture, the mentor loop, privacy, design, testing, replay, e2e, CI, releasing); this file holds only rules, each pointing at the doc or code that explains it where there is one.

- Plain `make` lists every command; `make check` (lint, `swift test`, `make test-snapshots`) is what local validation runs; a make recipe stays one line, and logic beyond one command goes in a script in `scripts/`. CONTRIBUTING.md.
- Never make a live model call to build, test or verify: calls cost the captain API credits. `make run` and every check replay recorded fixtures with no key; `make run-live` and `make record` are the only targets that spend, and `make record` is only for deliberate recording. docs/replay.md.
- Prompts and schemas are versioned in `Sources/AthinaCore/Mentor/Prompts.swift`; bump the version when they change. A change that bumps it or adds a call kind re-records the committed fixtures live in the same change, a deliberate few-cents `make record`; a stale fixture fails `swift test`. docs/replay.md "The committed fixtures".
- Tests replay `Tests/AthinaCoreTests/Fixtures/Replay` or use `ScriptedClaudeClient`, never the network. Only `MentorLoop.perform` reaches the `ClaudeClient` seam, only to `api.anthropic.com`, only with a key the user pasted into Settings > Models; never search for a key. docs/replay.md, docs/privacy.md.
- Model ids and prices live in `Sources/AthinaCore/Claude/ModelCatalog.swift` with the date they were checked.
- Several Athinas share one Mac: address one by pid, never quit or script Athina by name, read a replay's directory from its `Athina started: pid <pid> in <directory>` line rather than choosing one, and never drop `--replay` from `open -n build/Athina.app` (a bare `open -n` starts a second live Athina on the live journal, settings and bill). docs/replay.md "Replays side by side", CONTRIBUTING.md "Build, run, test".
- Everything time-based reads the injected `AthinaClock`, never `Date()` or `Task.sleep` (only system measurements and UI polling stay real); tests advance an `AdjustableClock` and wait on published events, and a replay's clock can run faster. docs/replay.md "A faster clock".
- Check UI without a person at the screen: `Athina --snapshot <dir>` renders every window off screen with no permissions or key, and `open -n build/Athina.app --args --replay <dir> --open debug` (or `settings:<pane>`, `history`) opens a window for `screencapture -l <window id>`. CONTRIBUTING.md "Build, run, test", docs/debug-panel.md.
- UI changes keep to the HIG choices in docs/design.md, with `StatusLabel`/`StatusBadge` for status.
- Approved images come only from CI: never commit renders from a Mac, take them with `make approve` (the `ui-snapshots` baselines, smoke references and e2e checkpoints from CI's runs of HEAD, all or none), and approve only a drift the change meant. A new snapshot needs a line in `SnapshotShard.assignment`; sample data stands still at `Snapshots.referenceDate`, and a view that moves on its own honours `drawsStill`. docs/ci.md.
- `ui-snapshots` runs on a pull request only while it carries the `merge-checks` label, never through a dispatch, whose checks a pull request ignores; the `main` ruleset requires `build-and-test`, `lint`, `e2e-api`, `ui-snapshots` and `ui-snapshots-smoke`. docs/ci.md.
- End-to-end checks go only through `scripts/e2e/athina-e2e`, called bare (never inside `lockf`), never hand-written driving. A validation's evidence runs the API tier (`run --tier api`) for anything in Athina's own windows, and the real-screen tier only for a change to the menu bar item, toast dismissal, the Settings links or sensing. docs/e2e.md.
- Give every control a scenario touches an accessibility identifier; the system-drawn exceptions are the Settings toolbar tabs, found by label, and a window's title-bar buttons, found by subrole such as `AXCloseButton`. docs/e2e.md "The control API".
- The control API exists only under the `ControlAPI` package trait (the development bundle) and in an unsandboxed replay (`ControlMode`); never add it to a release build, which `scripts/check-no-control-api.sh` refuses. docs/e2e.md "The control API".
- Swift follows Google's Swift Style Guide: `make format`, and `make lint` must pass, public declarations' doc comments included. docs/code-style.md lists the rules the linter cannot see, how to move the Xcode pin in `.xcode-version` (one deliberate commit that also refreshes both baseline sets, docs/ci.md) and the recipe for rebasing a branch from before the reformat.
- Never edit a generated file; change its source and rerun: the app icon, the menu bar mark and the README icon come from the masters in `Resources/Mark`, `scripts/mark-assets.swift` and its variant table through `make icons` (`MarkAssetTests` fails when they fall out of step), and `Athina.xcodeproj` from `project.yml` through `make xcodeproj`. docs/design.md, docs/releasing.md "The Xcode project".
- A dependency or framework added to the package's `Athina` target goes into `project.yml` too, except the `ControlAPI`-conditional `AthinaControl`, which the App Store build never carries. docs/releasing.md "The Xcode project".
- Screen Recording and Accessibility are granted by the captain in System Settings and never from a shell, and the optional Microphone and Speech Recognition only by the captain too; the app degrades to the modes README.md "Permissions" lists, and idle time needs no permission.
- The captain's Mac has no signing identity, so builds are signed ad hoc: a permission System Settings shows on but the app reports missing is bound to an old build, and the first key read after a rebuild can raise a keychain prompt only the captain can answer, until which no live call is made. docs/releasing.md "Code signing".
- The direct-download release comes only from `make release`, with Apple credentials only from `ATHINA_RELEASE_IDENTITY` and `ATHINA_NOTARY_PROFILE`; the version is set only in `Resources/Info.plist`, and each entitlement is justified in a comment in `Resources/Athina.entitlements`. docs/releasing.md.
- Performance numbers: `make measure` while the app runs. CONTRIBUTING.md.
- Every gating decision is a pure function in `MentorScheduler` (`triageGate`, `mentorGate`, `refreshGate`, `publishGate` for showing a finished suggestion, `followUpGate` for a spoken question); add new gating conditions there, not in the loop or the UI. The mentorship contexts are enforced in `triageGate`, `mentorGate`, and `refreshGate` only. docs/mentor-loop.md.
- Settings editors must not bind a control straight to a field `validated()` normalizes: `AppState.settings.didSet` re-validates on every keystroke, so a name would be trimmed and an empty new row dropped mid-edit. Edit a local copy and commit it (see `ContextsSettings.swift`).
- `SuggestionCategory`'s raw values are the schema enum the model must emit, so a multi-word case needs an explicit snake_case raw value matching the prompt text. Enum names reach the model; renaming one is a prompt change.
- Journal schema changes: `migrate` uses `CREATE TABLE IF NOT EXISTS`, which never alters a table an older build created, so a new column must also go through `addColumn` (`Journal.swift`) or it is missing on every existing journal, and a removed one through `dropColumn` or an older NOT NULL column fails every insert. A new table also needs a line in `clear(at:)` and in `applyRetention`. docs/architecture.md "Journal".
- Callout safety lives in `CalloutAnchor` (pure, `Sources/AthinaCore/Mentor/Callout.swift`): every reason a callout is refused or taken down is a case there with a test; the overlay only draws. Callouts need Accessibility for the window frame, so screen-only mode never draws one. docs/mentor-loop.md "Callouts".
- Voice: speech recognition is on-device only (`Sources/Athina/Voice`), lives in the app target, and is never touched by tests; reading suggestions aloud is deferred, not built; Microphone and Speech Recognition are optional permissions only the captain can grant. Push-to-talk uses Carbon's hotkey release event, so no Input Monitoring is ever requested. The debug panel's Talk back field sends typed words down the same path a released key does, which is how follow-ups are checked and recorded without a microphone. docs/mentor-loop.md "Talking back".
- The app is Athina; the word mentor is still the vocabulary of what it does. Product names are Athina (`Athina.app`, `AthinaCore`, `AthinaClock`, `com.ahcarpenter.athina`); the strong tier, its calls, gates, loop, settings key and mentorship contexts stay mentor (`MentorLoop`, `MentorScheduler.mentorGate`, `MentorSettings`, the `mentor` key in `settings.json`, the Mentor tier label). What the model is told still says Mentor (`Prompts.swift`, `ContextBuilder`'s history line): changing it bumps the prompt version and needs a live re-record, so it moves in one deliberate change.
- Files the owner keeps move with the name, never abandoned: `DataMigration` (`Sources/AthinaCore/Settings/DataMigration.swift`), `PreferencesMigration` and `KeyMigration` copy the journal folder, the preferences domain and the API key from Mentor once, leave the old copies in place, and never overwrite what Athina itself has written; their tests use in-memory stores and a throwaway domain, never the login keychain. docs/coming-from-mentor.md.
- One binary runs sandboxed (the Xcode project's App Store target) or not, decided at runtime by `RuntimeEnvironment` from the process's own entitlement, never a compile flag. Take the preferences domain and keychain service from `AppPaths`, never the literal id; a new flag or channel that names a path goes through `RuntimeEnvironment.refusal(reading:for:)`/`refusal(writing:for:)`, and tests pass an explicit environment for both answers. docs/releasing.md "A sandboxed build".
- The core type is `ActivityObservation`, not `Observation`: that name collides with Apple's Observation module inside `@Observable` macro expansions.
- Never use the em dash character anywhere in this repository; use a plain dash.
